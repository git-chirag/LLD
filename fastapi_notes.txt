4/ What is ASGI and how is it different from WSGI?
🧠 What is ASGI and how is it different from WSGI?
⚙️ 1. What is WSGI?
🔹 Definition
WSGI (Web Server Gateway Interface) is a standard that defines how a web server communicates with a Python web application.
🔹 How it works
Request comes from client
Web server (like Gunicorn) passes it to app
App processes and returns response
❗ Key limitation
WSGI is synchronous

👉 It handles:

one request per thread/process
🔻 Problem

If a request is waiting (e.g., DB call):

thread is blocked ❌
⚙️ 2. What is ASGI?
🔹 Definition
ASGI (Asynchronous Server Gateway Interface) is the modern version of WSGI that supports asynchronous communication.
🔹 How it works
Uses event loop
Can handle multiple requests concurrently
Supports async/await
✅ Key advantage
Non-blocking I/O

👉 While waiting:

can process other requests
🔥 Key Differences
Feature	WSGI	ASGI
Model	Synchronous	Asynchronous
Concurrency	Thread/process-based	Event loop-based
Performance	Lower under high load	Higher for I/O tasks
WebSockets	Not supported	Supported
Use case	Traditional apps	Modern APIs, real-time apps
🧠 Simple analogy
WSGI:
1 worker → handles 1 customer at a time

ASGI:
1 worker → handles multiple customers by switching when waiting
⚡ Real-world implication
Django (WSGI)
good for:
traditional apps
struggles with:
high concurrency
real-time systems
FastAPI (ASGI)
ideal for:
APIs
microservices
ML inference
real-time apps
🧠 Clean Interview Answer
WSGI is a synchronous interface between a web server and a Python application, where each request is handled in a blocking manner, typically requiring a separate thread or process. ASGI is the asynchronous successor to WSGI, which supports non-blocking I/O and allows a single process to handle multiple concurrent requests using an event loop. This makes ASGI more suitable for modern applications like APIs, real-time systems, and high-concurrency workloads, which is why frameworks like FastAPI are built on ASGI.
💡 Bonus (VERY important for your case)
FastAPI uses ASGI servers like Uvicorn, which is why it can handle many concurrent requests efficiently, unlike traditional WSGI-based frameworks.
🏁 One-liner to remember
WSGI = sync, blocking  
ASGI = async, non-blocking, scalable

import time

app = FastAPI()

@app.middleware("http")

    response = await call_next(request)  # pass request to next layer

    duration = time.time() - start
    print(f"Request took {duration:.4f} seconds")

    return response

response → modify before sending back

🔐 3. Step-by-step JWT Authentication
🔹 Install dependency
pip install python-jose passlib
🔹 Create token
from jose import jwt
from datetime import datetime, timedelta

SECRET_KEY = "secret"
ALGORITHM = "HS256"

def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=30)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
🔹 Login endpoint
from fastapi import FastAPI, HTTPException

app = FastAPI()

fake_user = {"username": "chirag", "password": "123"}

@app.post("/login")
def login(username: str, password: str):
    if username != fake_user["username"] or password != fake_user["password"]:
        raise HTTPException(status_code=401, detail="Invalid credentials")

    token = create_access_token({"sub": username})
    return {"access_token": token}
🔐 4. Extract current user (Dependency)
from fastapi import Depends
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")
🔹 Decode token
def get_current_user(token: str = Depends(oauth2_scheme)):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username = payload.get("sub")
        return {"username": username}
    except:
        raise HTTPException(status_code=401, detail="Invalid token")
🔐 5. Protect routes (Authentication)
@app.get("/protected")
def protected(user=Depends(get_current_user)):
    return {"message": f"Hello {user['username']}"}

👉 Request:

GET /protected
Authorization: Bearer <token>
🧠 6. Authorization (Role-based)
🔹 Add roles
def get_current_admin(user=Depends(get_current_user)):
    if user["username"] != "admin":
        raise HTTPException(status_code=403, detail="Not authorized")
    return user
🔹 Use it
@app.get("/admin")
def admin_route(user=Depends(get_current_admin)):
    return {"message": "Admin access granted"}

1. User logs in → gets JWT token
2. Client sends token in Authorization header
3. FastAPI extracts token using Depends()
4. Token is validated
5. User is authenticated
6. Role checks → authorization

✔ Uses dependency injection
✔ Clean separation of concerns
✔ Reusable auth logic
✔ Works well with async APIs
🧠 Clean Interview Answer
In FastAPI, authentication is typically implemented using JWT tokens along with OAuth2PasswordBearer. A user logs in and receives a token, which is then sent in the Authorization header for subsequent requests. FastAPI uses dependency injection with Depends to extract and validate the token and identify the user. Authorization is implemented on top of this by checking user roles or permissions inside dependencies. This approach keeps authentication and authorization logic modular and reusable.

🧠 How do you connect FastAPI to a database?

FastAPI connects to databases using libraries like SQLAlchemy (ORM) or async drivers, and manages connections using dependency injection.

⚙️ 1. Common Choices
✔ SQLAlchemy (most common, sync + async)
✔ Databases library (async)
✔ psycopg2 / MySQL drivers (low-level)

👉 In interviews → say SQLAlchemy

⚙️ 2. Basic Setup (SQLAlchemy - Sync)
🔹 Step 1: Create DB connection
from sqlalchemy import create_engine

DATABASE_URL = "sqlite:///./test.db"

engine = create_engine(DATABASE_URL)
🔹 Step 2: Create Session
from sqlalchemy.orm import sessionmaker

SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False)
🔹 Step 3: Dependency (VERY IMPORTANT)
from fastapi import Depends

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
⚙️ 3. Use DB in FastAPI Endpoint
from fastapi import FastAPI, Depends
from sqlalchemy.orm import Session

app = FastAPI()

@app.get("/users")
def get_users(db: Session = Depends(get_db)):
    return {"message": "DB connected"}
🧠 What’s happening
✔ get_db() creates DB session
✔ FastAPI injects it using Depends
✔ session is closed after request
⚙️ 4. Example with Model
🔹 Define Model
from sqlalchemy import Column, Integer, String
from sqlalchemy.orm import declarative_base

Base = declarative_base()

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    name = Column(String)
🔹 Query Data
@app.get("/users")

    users = db.query(User).all()
    return users
⚡ 5. Async DB (Modern Approach)
🔹 Using async SQLAlchemy
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession

engine = create_async_engine("sqlite+aiosqlite:///./test.db")

AsyncSessionLocal = sessionmaker(engine, class_=AsyncSession)
🔹 Dependency
async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
🔹 Endpoint
@app.get("/users")
async def get_users(db: AsyncSession = Depends(get_db)):

In FastAPI, database connections are typically handled using an ORM like SQLAlchemy. This dependency is injected into route handlers using Depends, ensuring that each request gets its own session, which is properly closed after use. FastAPI also supports asynchronous database access using async drivers and SQLAlchemy’s async features.
