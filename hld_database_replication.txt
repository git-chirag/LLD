Primary-Replica Architecture

Most common architecture.

          App
            |
      -------------
      |           |
   Writes       Reads
      |           |
   Primary    Replicas
Primary

Responsible for:

INSERT
UPDATE
DELETE

Only one source of truth.

Replica

Responsible for:

SELECT

Copies data from primary.

Cannot accept writes (typically).

Replication Flow

Example:

UPDATE account
SET balance = 100
WHERE id = 1;

Flow:

Write hits Primary
        |
Primary updates data
        |
Change replicated
        |
Replica updates data
Types of Replication
Synchronous Replication
Client
  |
Primary
  |
Replica

Primary waits for replica acknowledgement.

Flow:

Write Primary
      |
Write Replica
      |
ACK Replica
      |
ACK Client
Advantages

Strong consistency.

After write:

All replicas see latest value.
Disadvantages

Higher latency.

If replica is slow:

Entire write becomes slow.

Used for:

Banking
Payments
Financial systems
Asynchronous Replication

Most common.

Flow:

Write Primary
      |
ACK Client
      |
Replicate Later
Advantages

Fast writes.

Disadvantages

Replication lag.

Replica may contain stale data.

Used by:

MySQL Replicas
Postgres Replicas
Most production systems

Consistency vs Availability

Replication introduces tradeoffs.

Question:

Primary updated:

Balance = 100

Replica still has:

Balance = 90

Would you:

Option A

Wait for replica.

Consistent
Option B

Return stale value.

Available

This becomes CAP discussion.

Replication vs Backup

Very common trick question.

Replication:

Live copy

Changes immediately propagated.

Backup:

Snapshot at a point in time

Used for recovery.

If you delete data:

DELETE FROM users;

Replication copies deletion too.

Not a backup.

Interview Questions
Why use replication?
Read scaling

Disaster recovery
Can replicas be stale?

Yes.

Due to replication lag.

What is replication lag?

Delay between primary update and replica update.

What problems can replication lag cause?
Stale reads
Read-after-write inconsistency
How do you solve stale reads?
Read from primary
Sticky sessions
Accept eventual consistency
Why not send writes to replicas?

Would create conflicts.

Primary remains source of truth.

What happens if primary dies?

Failover.

Promote replica to new primary.
